# KitHarness 迭代计划

目标：在 AutoHarness 基础上，逐步实现可靠的技能演进、任务感知召回和可复现的效果评估。
保留反思者（reflector）、整理者（curator）、确定性执行器（promoter）和生命周期退役机制。

## 工作约定

- 默认每次推进一个可独立验证的小步骤；用户明确要求多步时依次推进，每一步通过验收后独立标记。
- 状态使用：`待开始`、`进行中`、`已完成`。未通过验收的步骤不能标记完成。
- 用户明确要求提交后，才执行 Git commit；用户明确要求推送后，才执行 Git push。
- 每次汇报修改范围、验证结果和剩余限制，不将计划功能或未经测量的指标当作已完成成果。
- 开发测试使用隔离目录，不修改个人真实技能库。真实模型评测开始前明确调用规模与预算。

- 执行规则：同一批次先按原顺序执行内容变更，再执行合并归档；最终 verdicts 仍与原提案顺序一一对应。
- 拒绝规则：目标任一次内容变更失败，依赖它的归档均拒绝；目标自身也被安排归档时，拒绝归档到该目标，避免循环或中间目标消失。
- 追踪方式：依赖拒绝记录原因与 `depends_on`，后者指向当前批次 verdicts 的零起始位置。
- 范围限制：仅处理一次队列 claim 内已入队的操作依赖；MCP 校验后未入队的失败提案不在此批次中。本步不证明语义上的知识完整迁移，不提供跨批次/跨项目事务或失败后的整体回滚。

### 6.2 后台任务限额和用量

- [x] 反思者、整理者与 fork 调用共用超时、项目并发、共享全局并发和 CLI 单次预算配置。
- [x] 默认子进程超时 180 秒、项目并发 1、共享全局并发 2、每次传入 1 美元预算；非法配置回退到安全默认值。
- [x] POSIX 超时终止进程组及登记写入者；管理进程崩溃后，直接子进程持有的并发锁仍有效。
- [x] 超时、预算耗尽、启动失败及普通子进程报错均隔离提案，保留队列，禁止自动执行；并发满时跳过本次运行。
- [x] 跳过/失败不推进对话已处理偏移；运行记录保存原因及宿主报告的有效数值用量，不保存原始模型响应；落盘重试保留用量。
- 行为调整：不再采用“子进程崩溃后继续落盘其已入队提案”的旧策略。
- 边界：预算由 Claude CLI 执行，不是精确账单上限或月度限额；未知用量标记不可用。超时约束模型子进程调用，不约束磁盘操作；不提供自动补跑调度器。

### 6.3 版本保留

- [x] 提供单技能 `versions prune` 命令，默认预览，显式 `--apply` 才删除；默认保留最近 10 个版本。
- [x] 与修改/恢复共用技能锁，额外保护未完成事务和最近可恢复目录；损坏、符号链接及非法数量阻止清理。
- [x] 删除前原子隔离候选目录，避免中断后版本列表出现半删快照。
- [x] 永久保留完成日志和操作回执；快照清理后，旧 claim 仍复用原结果，不重复修改技能。
- 边界：默认不自动清理；审计记录继续增长。清理中断遗留的隔离目录需人工检查后清除，整库备份/归档副本不在此命令范围内。

- [x] 整理者改为累计项目内的主会话工具调用；跨会话保留，与反思的工具调用单位一致。
- [x] Stop 判断是否跨过阈值，一次最多发起一次整理并保留余量；反思清零、SessionEnd 清理、纯聊天和插件子会话不会错误推进或清掉整理进度。
- [x] 用跨进程锁领取进度，防止并发 Stop 重复领取；同步启动失败不消费进度，每次重试使用独立 run ID。
- [x] 同时到期时优先发起整理，保留反思计数供后续 Stop 或 SessionEnd 使用；启动成功但进度保存失败时也不追加反思任务。
- [x] 整理频率 0 可暂停，负值/非法值回退默认；原有 requests 仍为对话轮数，不伪造历史工具次数或修改旧 sidecar。
- 边界：这是触发与启动控制，不是补跑调度器；实际运行仍受第六步限额约束。启动和进度保存不是事务，中间故障可能再次请求整理，不宣称模型执行恰好一次。
