# KitHarness 迭代计划

目标：在 AutoHarness 基础上，逐步实现可靠的技能演进、任务感知召回和可复现的效果评估。
保留反思者（reflector）、整理者（curator）、确定性执行器（promoter）和生命周期退役机制。

## 工作约定

- 每次只推进一个可独立验证的小步骤；完成后更新本文件并汇报结果。
- 状态使用：`待开始`、`进行中`、`已完成`。未通过验收的步骤不能标记完成。
- 用户明确要求提交后，才执行 Git commit；用户明确要求推送后，才执行 Git push。
- 每次汇报修改范围、验证结果和剩余限制，不将计划功能或未经测量的指标当作已完成成果。
- 开发测试使用隔离目录，不修改个人真实技能库。真实模型评测开始前明确调用规模与预算。

## 步骤 1：归档保护

本步将模型提出的 `delete` 限定为明确指定 `absorbed_into` 的合并归档。
缺失目标时直接拒绝，不从自然语言 `reason` 猜测意图。普通生命周期退役继续通过现有生命周期管理器归档。
这是有意收紧模型写入接口：历史队列中缺少目标的 `delete` 会被拒绝并保留原技能。

本步不保证同批依赖或多文件事务；已有目标更新失败后能否归档，留待步骤 2 处理。
