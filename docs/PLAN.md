# KitHarness 迭代计划

目标：在 AutoHarness 基础上，逐步实现可靠的技能演进、任务感知召回和可复现的效果评估。
保留反思者（reflector）、整理者（curator）、确定性执行器（promoter）和生命周期退役机制。

## 工作约定

- 默认每次推进一个可独立验证的小步骤；用户明确要求多步时依次推进，每一步通过验收后独立标记。
- 状态使用：`待开始`、`进行中`、`已完成`。未通过验收的步骤不能标记完成。
- 用户明确要求提交后，才执行 Git commit；用户明确要求推送后，才执行 Git push。
- 每次汇报修改范围、验证结果和剩余限制，不将计划功能或未经测量的指标当作已完成成果。
- 开发测试使用隔离目录，不修改个人真实技能库。真实模型评测开始前明确调用规模与预算。

## 步骤 1：归档保护

这是有意收紧模型写入接口：历史队列中缺少目标的 `delete` 会被拒绝并保留原技能。

## 步骤 2：同批合并依赖

- 当前状态：已完成，2026-11-02。
- 提交记录：本轮按用户要求创建步骤 2 的本地提交；本次不推送。
- 执行规则：同一批次先按原顺序执行内容变更，再执行合并归档；最终 verdicts 仍与原提案顺序一一对应。
- 拒绝规则：目标任一次内容变更失败，依赖它的归档均拒绝；目标自身也被安排归档时，拒绝归档到该目标，避免循环或中间目标消失。
- 追踪方式：依赖拒绝记录原因与 `depends_on`，后者指向当前批次 verdicts 的零起始位置。
- 范围限制：仅处理一次队列 claim 内已入队的操作依赖；MCP 校验后未入队的失败提案不在此批次中。本步不证明语义上的知识完整迁移，不提供跨批次/跨项目事务或失败后的整体回滚。

验证记录：

- 新增 25 项回归用例，覆盖目标创建/更新/补丁失败、归档先入队、目标多次变更、独立合并、全局目标、循环/链式合并、子文件移除失败、临时 I/O 重试及遗留 claim 恢复。
- 归档执行时检查目标内容已落地；拒绝操作不改变来源技能的正文、附件、sidecar 或 ledger。
- 针对已有测试中的新建目标拒绝场景，增加依赖原因和位置断言。
- Python 3.12 全量非 live 测试：**871 passed, 1 deselected**。
- Ruff、`git diff --check`、文档链接检查通过。
- 不涉及真实模型调用，未修改个人真实技能库。

### 步骤 5：完整版本与崩溃恢复

- 状态：已完成。
