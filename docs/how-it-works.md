# 技能学习流程

[返回 README](../README.md) · [配置参考](configuration.md)

KitHarness 在 Claude Code 旁运行一条学习流水线。生成的技能是宿主可直接识别的原生文件，继续通过名称和描述参与原生召回。插件另行提供两种召回方式：默认的 `task` 模式在提交提示时匹配词项，`catalog` 模式在会话启动时提供分组目录。两种模式都仅处理插件生成的技能，并分别记录检索与实际使用。

| 组件 | 职责 |
|---|---|
| **CAP · 会话捕获** | 由钩子驱动，捕获用户输入、代理输出和工具输入输出，在向外传递时脱敏，并引用宿主日志而非复制整份日志。按工具调用次数确定性触发反思，不对内容作判断。 |
| **REF · 反思者** | 读取会话片段，对照已有技能索引，提出新增、合并、补丁、移除辅助文件或删除等意图，并附正文、差异或路径，以及原因和证据。新经验与旧技能矛盾时，须在同次运行中修正旧内容。反思者只提案，没有写入工具；`fork` 继承的写入工具也会被钩子拦截。 |
| **promoter · 校验与落盘** | 唯一负责写入的组件。在内存中校验安全性、结构、账本、完整性和自身生成标记，通过后以原子重命名写入技能目录。完整描述支持中英文触发条件，长度限制独立于索引预览。合并必须指向仍存在且由插件管理的承接技能，虚构目标会导致意图被拒绝。每次运行均记录成功与拒绝结果。 |
| **IDX · 技能召回** | 对完整名称、类别和描述使用字段加权 BM25，结合中英文词项打分，在字节与条目预算内选择技能，并展示简短预览。只读 CLI 可解释命中词、得分和排除原因。`catalog` 模式保留启动分组目录；上次运行报告仍在 `SessionStart` 提供。这是词项检索，尚无任务成功率提升的实验证据。 |
| **MNG · 生命周期管理** | 无常驻守护进程，每个会话启动时按需重算一次。按“加载次数／技能创建后所在层收到的请求数”排序，电脑闲置不会使技能老化。分别记录加载、查看和补丁；只有实际加载计入使用率。试用期技能正常召回、不占成熟容量、不会被归档。转正审查仅归档既未加载也未查看的技能；成熟池超过容量时，再优先归档低使用率技能。归档通过移动目录完成，可移回恢复。 |
| **curator · 整理者** | 以较低频率审视整个技能库，将近似重复项合并到能承接内容的技能中。开始前为项目和全局两棵技能树创建快照，支持恢复跨技能合并。 |
| **LED · 变更账本** | 每个技能独立维护只追加的附属记录，保存创建或修改原因、证据和反思进度水位。账本与技能正文分离，避免干扰召回内容。 |

## 演示：观察一次技能学习

插件行为以普通文件保存在磁盘上，可通过查看这些文件观察学习过程。为了缩短演示等待时间，可先在配置中降低阈值：

```json
{
  "env": {
    "KITHARNESS_REFLECT_EVERY_N": "3",
    "KITHARNESS_MATURITY_PROJECT": "5",
    "KITHARNESS_CAPACITY_PROJECT": "2"
  }
}
```

### 1. 观察流水线触发

正常进行几轮需要工具调用的工作，例如调试问题或梳理工作流程。工具调用量达到阈值的轮次结束后，后台反思被触发，主会话可以继续。相关记录位于状态目录：

```text
.claude/kitharness/             # 项目层；全局层为 ~/.claude/kitharness/
  requests                     # 所在层的请求计数，用作使用率分母
  session-<id>                 # 距离下次反思的工具调用计数
  offset-<id>                  # 上次捕获窗口结束位置的字节水位
  intents/                     # 等待执行器处理的技能提案
  runs/<run-id>.json           # 本次提案、落盘和拒绝结果，以及原因
  last_run.json                # 等待下次会话启动时报告的摘要
  snapshots/                   # 整理者合并前保存的技能树压缩快照
```

### 2. 查看新技能

若调用 `stage_skill` 后未出现技能，先检查工具返回的 `ok` 和 `errors`。`missing/invalid frontmatter` 是正文格式错误，不表示项目偏好不受支持。创建或更新时，正文必须以 `---` 包围的 YAML 元数据开头，包含 `name` 和带使用条件的 `description`；修正后重试。前置校验失败的提案不会进入队列，也不会生成落盘运行报告。

正文行数限制同样在工具调用时检查：默认最多 25 个非空行，不含 YAML 元数据。`altitude` 错误应通过精简规则或将详细示例移到被正文引用的 `references/` 文件修正；不要为了通过检查而补写未确认的偏好。

工具返回 `ok: true`、`status: queued` 表示提案已入队。当前轮次结束后的 `Stop` 钩子才会调用执行器，最终是否落盘应以文件或运行记录为准。

反思通过校验并落盘后，项目技能出现在 `.claude/skills/`，跨项目通用技能出现在 `~/.claude/skills/`。使用 `ls -la` 查看隐藏的附属文件：

```text
.claude/skills/<name>/
  SKILL.md                     # 原生格式的技能文件
  .ledger.jsonl                # 创建和修改原因，只追加
  .sidecar.json                # 生命周期计数
  references/evidence-*.md     # 支撑账本记录的会话证据片段
  scripts/ templates/ ...      # 可选的脚本、模板等辅助文件
```

### 3. 查看变更依据

读取技能目录内的 `.ledger.jsonl`，每个生命周期事件占一行。以下示意创建和修补记录：

```json
{"action": "create", "reason": "用户询问了更新插件的正确命令……", "evidence": "references/evidence-21cd22cc.md"}
{"action": "patch", "reason": "用户发现会话内还需要执行 /reload-plugins……", "evidence": "references/evidence-1a4ec51d.md"}
```

`action`、`reason` 和 `evidence` 共同记录变更及其依据。证据文件由执行器从真实会话中截取、脱敏并生成，按内容寻址，文件名由系统确定。

### 4. 观察已有技能更新

再次遇到相同场景并提供修正，例如“这里缺少一步”，让下一次反思处理。已有技能的 `SKILL.md` 会被修订，账本追加 `patch` 或 `update` 记录。对于项目层技能，可用 `git diff` 查看具体修改。

### 5. 在后续会话中召回

新会话启动时会收到上次运行的单行报告，包括被拒绝的提案。默认 `task` 模式在提交提示后选择相关技能；若配置为 `catalog`，则在启动时提供分组索引。宿主原生召回机制继续工作。

### 6. 区分使用、查看和改进

读取 `.sidecar.json` 可查看三类计数：

- `use`：模型实际加载技能，计入使用率。
- `view`：会话读取过技能目录，说明技能被查看过，不代表已按其执行。
- `patch`：执行器落盘了一次改进；后续的 `use` 可用于观察改进后是否再次使用。

### 7. 观察归档与恢复

转正审查和容量淘汰都会将技能目录移入 `.claude/skills/.archive/<name>/`，连同账本和证据一起保留，并移出召回范围。

转正审查仅归档整个试用期内既未使用也未查看的技能。成熟技能池超过容量后，优先归档使用率最低的技能。将目录移回即可恢复技能及其历史。

使用演示中的较小阈值，可在单次会话内观察这些行为；默认配置通常需要数百次请求。合并的来源技能也通过归档保存，但账本会注明承接内容的目标技能，以便区分合并与淘汰。

### 8. 确认管理边界

插件生成的技能带有专属账本标记。没有该标记的技能，包括用户手写或另行安装的技能，不会被执行器和生命周期管理器修改。

## MCP 服务命名

`.claude-plugin/plugin.json` 将服务注册为 `stage_skill`，代理定义中引用的完整工具名是 `mcp__plugin_kitharness_stage_skill__stage_skill`。插件运行时会根据插件 ID `kitharness` 和服务键自动生成这个名称。

手动注册同一服务时，工具名通常为 `mcp__stage_skill__stage_skill`，与代理允许列表中的插件命名空间不一致。因此应按上述方式安装为插件。

服务声明位于插件清单中，未放在仓库根目录的 `.mcp.json` 中。因为插件根目录也是仓库根目录，根目录的 `.mcp.json` 同时会被识别为项目配置；其优先级高于执行相同命令的插件服务，可能导致在本仓库内运行的反思者无法使用所需工具。
