# 可靠技能演进：幂等、恢复和回滚

KitHarness 保留反思者、整理者、promoter 和生命周期管理器。模型只提出技能修改，可靠性机制在确定性执行器中实现，不额外调用模型。

## 写入流程

1. 队列追加时生成随机 `operation_id`，调用方不能指定身份。正文/附件检测到凭据时 MCP 拒绝入队，变更说明和证据先脱敏。
2. 领取批次后，为历史队列补齐并持久化操作 ID。只读 `intent_queue.read()` 保持原有提案视图；`take()` 返回带身份的提案。
3. promoter 先恢复遗留的未完成事务，再处理批内内容修改和依赖归档。
4. 对通过验证的技能操作，获取技能的稳定锁，将完整目录保存为操作前版本，再发布 `prepared` 日志。
5. 写入正文、附件、sidecar 和 ledger；成功后将事务日志变为 `committed`，保存脱敏后的操作结果。
6. 写入项目层的独立操作回执，再生成批次报告。报告失败时，重试复用已保存的结果。

新队列的追加和原子文件替换会刷新文件数据；支持目录 fsync 的系统还会刷新重命名元数据。

## 崩溃时如何恢复

| 中断位置 | 恢复行为 |
| --- | --- |
| 快照完成前 | 技能尚未修改；重新验证和执行 |
| `prepared` 后、完成标记前 | 从完整快照恢复正文、附件、权限和元数据，然后允许原队列重试 |
| 归档目录移动后、完成标记前 | 恢复原技能，校验并移除属于本操作的归档副本，再重试 |
| `committed` 后、独立回执前 | 使用事务日志保存的结果补写回执，不再修改技能或重复计数 |
| 回执成功、批次报告失败 | 使用回执重新生成报告 |
| 恢复过程中再次失败 | 保留日志、快照和队列，停止本轮处理，后续再恢复 |

SessionStart 会在生命周期管理和召回前恢复未完成的技能事务。正常 drain 和直接 promoter 调用也会先恢复。

同一个队列操作的重试复用同一 ID；两次独立的工具调用即使内容相同，也会得到不同 ID，按两次操作处理。
历史队列在领取时自动迁移，不改写已完成的旧历史。损坏或与内容不匹配的回执会阻止执行，不会被忽略后再次落盘。

## 查看版本和回滚

在仓库根目录使用 Python 3.11+。以下路径指向项目的配置根目录（包含 `skills/` 的 `.claude`），不是项目源码目录。

```sh
PYTHONPATH=src python3.12 -m autoharness.lib.versions list dates --root /path/to/project/.claude
PYTHONPATH=src python3.12 -m autoharness.lib.versions rollback dates --root /path/to/project/.claude --version VERSION_ID
```

全局层可显式增加 `--level global --root /path/to/global-config`。禁用全局层时，不能执行全局回滚。

列表中的版本是**操作前快照**，包含 `id`、`existed`、时间、动作和操作 ID。第一次创建前的 `existed: false` 版本不能用于手动恢复。
回滚前会核对目录摘要和技能归属；快照损坏、包含符号链接、目标变成用户技能时拒绝恢复。
回滚会先保存当前目录，返回 `undo_version`；用该 ID 可以撤销本次回滚。
回滚可以恢复归档前的技能；原有归档副本仍保留，不自动清理。

目录的所有文件、权限、sidecar 和 ledger 都恢复到所选快照，因此使用计数也可能回到旧值。
回滚动作的审计记录保存在技能目录以外的事务历史中。

## 安全边界

- 这是**单个技能操作的故障恢复**，不提供整个合并批次或跨项目的整体事务。
- 宿主直接 Read 文件时不会获取这些锁，操作进行中仍可能看到过渡状态；恢复前的短暂中断也不等于文件系统快照隔离。
- 写入者、计数更新和归档共享稳定锁，避免恢复覆盖同时发生的插件计数更新；外部编辑器不受锁约束。
- 快照上限为每个技能 32 MB、4000 个目录项；超限时在修改前拒绝，避免无界复制。
- 版本支持[默认预览的手动清理](runtime-controls.md)，保留未完成事务的恢复依据；完成日志和回执不淘汰。恢复失败可能需要先解决磁盘空间、权限或快照损坏问题。
- 操作历史保留在本地配置根目录的 `autoharness/versions`、`transactions`、`operations` 中，不写入技能正文。快照叶目录权限为 0700，新元数据文件为 0600（POSIX）。
- 脱敏保护新写出的说明、证据和 ledger，不自动清洗旧日志；旧内容的快照仍属于本地敏感数据。MCP 正文凭据检查基于现有规则，不是所有秘密的通用检测器。
- 模型未通过 MCP 校验、没有入队的提案仍不属于批内依赖图；技能的语义正确性和效果评估留待后续实现。

## 验证方式

回归测试使用临时技能库和虚构凭据。真实子进程测试在正文、ledger、完成日志、回执、归档和手动回滚写入后调用 `os._exit(77)`，模拟无法运行异常清理的进程退出。
恢复后检查正文、附件、计数和历史条目，确保队列操作只应用一次；还覆盖回滚撤销、快照篡改、符号链接和并发计数。
