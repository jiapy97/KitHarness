# 任务感知召回与上下文预算

本页对应第 9 步。默认按当前提交文本筛选技能，使用本地确定性算法，不调用模型、不生成 embedding、不读取外部服务。

## 任务从哪里来

新增 `UserPromptSubmit` hook，读取宿主提供的 `prompt`，通过 `hookSpecificOutput.additionalContext` 返回相关技能列表。这两个字段按[Claude Code 官方 hook 规范](https://code.claude.com/docs/en/hooks#userpromptsubmit)接入；本轮未运行真实模型集成测试。

默认 `task` 模式不再在 SessionStart 展开目录，SessionStart 仍负责恢复、生命周期检查和上次执行摘要。
每个提示提交事件独立检索，所以任务切换时会重新选择；没有匹配时不拿无关技能凑数。
插件启动的反思/整理子会话跳过这一入口，避免递归注入。反思与整理自己的比较索引仍读取完整描述，不受这里的 top-K 筛选影响。

`AUTOHARNESS_RECALL_MODE=catalog` 可切换到启动时的分类目录；该模式也受 top-K 和字节预算约束，提示提交时不重复注入。
已安装的缓存副本需要更新或重新加载插件，新增 hook 才会生效；本轮没有改写个人宿主配置或部署插件。

## 怎么排序、怎么解释

匹配字段只有技能名称、category 和完整 description，不索引正文、附件或使用计数。
英文按字母/数字词项切分并归一大小写和全半角，保留 C++、C# 这样的形式；中文连续片段拆成相邻双字片段。去除少量常见停用词，不做同义词推断或自动翻译。

排序采用字段加权 BM25：共享文档频率，字段内分别归一长度，`k1=1.2`、`b=0.75`；名称权重 3、description 权重 2、category 权重 1，再求和。
同分时项目层优先，然后按名称排序。输入遍历顺序不影响结果。
完整描述即使在显示预览里被截断，后半段仍参与匹配；默认上限内的描述不因预览变短而失去匹配词。

输入只扫描前 8000 个字符、最多 256 个不同词项；单个元数据文件最多读取 64 KB，单字段最多索引 8000 字符，超出前缀的信息不会参与本次检索。
读取范围只含启用层的 agent-created 技能；原生/用户技能、归档、识别到的符号链接和损坏记录不参与。单项读取失败跳过该项，不中断其他候选。

可以通过只读 CLI 查看完整排序依据，根目录是含 `skills/` 的 `.claude` 配置目录：

```sh
PYTHONPATH=src python3.12 -m autoharness.lib.recall --stdin --root /path/to/project/.claude --global-root /path/to/global/.claude
# 在 stdin 输入任务文本后结束输入；也可使用 --query '检查日期跨时区边界'
```

输出包括命中词、命中字段、贡献分数、总分，以及 `selected`、`no_match`、`top_k`、`budget` 等选择/排除原因。
贡献列表最多展示最强的 12 个命中词，更多词项仍可能参与总分。CLI 不回显完整查询；没有查询日志或缓存文件。
查询和元数据先按现有规则脱敏，诊断不保存提示原文。已有规则不能识别所有秘密；识别到的旧元数据凭据不会进入注入文本。

## 预算覆盖什么

| 配置 | 默认值 | 作用 |
| --- | --- | --- |
| `AUTOHARNESS_RECALL_MODE` | `task` | `task` 或 `catalog`；非法值回退 task |
| `AUTOHARNESS_RECALL_MAX_BYTES` | `4096` | 单个 hook 事件的插件注入文本 UTF-8 硬上限；0 关闭注入 |
| `AUTOHARNESS_RECALL_TOP_K` | `5` | 单次最多选入的技能数，必须是正整数 |
| `AUTOHARNESS_INDEX_DESC_MAX_CHARS` | `60` | 单条 description 预览长度，完整描述仍独立保存 |

标题、换行、分类标题、技能行、worktree 路径提示都计入预算。整个候选条目放不下时跳过，继续尝试后面的候选，不把一条路径或技能行切成半截。
目录模式先为上次执行摘要留出预算；摘要本身过长时不注入，但持久运行记录仍保留。
`AUTOHARNESS_INDEX_SUSPENDED=1` 停止技能索引注入，生命周期和使用计数机制照常运行。

报告中的 `token_estimate=ceil(UTF-8字节数/4)` 只是统一对照用的粗略代理值，**不是 Claude 实际 Token 或计费数据**，也不是实际 Token 上限。
硬保证针对解码后的插件文本字节数，不包含 JSON 转义开销、宿主包装、原生技能上下文、随后加载的正文、用户对话或其他插件。
每次提交独立限额；已注入的旧内容可能留在会话里，因此不是整个会话的累计预算。

检索本身不更新 use/view/patch，不把“展示过”当成“被采用”。没有新增学习、归档或落盘路径。

## 固定查询对照

数据：[20 个合成技能与 18 条标注查询](../evals/recall/fixture.json)，其中 16 条有相关项、2 条无相关项。中英文均有覆盖，也保留了一个无词项重合的同义改写失败案例。
结果：[可复现报告](../evals/recall/report.json)。重现命令：

```sh
PYTHONPATH=src python3.12 tools/evaluate_recall.py --output /tmp/kitharness-recall-report.json
```

| 策略 | 相关查询召回 | 正查询 MRR | 平均注入字节 | 平均估算 Token |
| --- | --- | --- | --- | --- |
| 完整分类目录 | 16/16，100% | 0.147 | 2092.0 | 523.0 |
| 同上限分类目录 | 4/16，25% | 0.080 | 642.0 | 161.0 |
| 任务 BM25 | 15/16，93.75% | 0.938 | 170.7 | 43.0 |

后两者都使用 top-K=5、字节上限=1200；原版式目录展示全部 20 条。1200 字节是固定实验配置，安装默认值仍是 4096。
平均大小按全部 18 条查询计算，相关召回和 MRR 按 16 条正查询计算。每条正查询恰有 1 个标注相关技能。
报告还包含逐查询选择、无关查询注入比例和精度；空返回在无相关查询上精度记为 1，在正查询上记为 0。

这是小型、人工标注的合成元数据集，许多查询与描述有直接词项重合，不是独立真实任务评测。
比较的是整个注入策略（排序、目录格式和选择），不单独隔离 BM25 的贡献；字节上限不一定在每条查询上触满。
完整目录天然具有这里的 100% 覆盖率，但注入量更大；任务策略保留了一次可见漏召回，不能宣称在所有输入上优于完整目录。
同义词、翻译、长描述前缀之外的信息和纯“继续”等缺少词项的提示都可能漏召回。下一步再评估真实任务成功率、成本和失败案例，本报告不提供这些结论。
