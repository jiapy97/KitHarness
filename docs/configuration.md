# 配置参考

[返回 README](../README.md)

配置项均为 `AUTOHARNESS_*` 环境变量，内置默认值。只有需要调整行为时才需设置。

### 管理范围

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `AUTOHARNESS_DISABLE_GLOBAL` | `0` | 设为 `1` 后仅管理项目层。全局创建意图会在暂存和落盘前被拒绝；全局请求、使用、查看计数，以及归档、孤立数据清扫、召回、整理快照和指标统计均跳过。已有全局技能保持原样，项目层学习继续运行。 |
| `AUTOHARNESS_GLOBAL_ROOT` | 未设置 | 替换全局层根目录，默认使用 `~/.claude`。未设置或空值均使用真实用户目录。适用于固定版本副本、CI 或评测等需要隔离生产技能库的场景。项目层仍以当前会话所在仓库为准。 |

### 学习频率

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `AUTOHARNESS_REFLECT_EVERY_N` | `50` | 反思频率，按**主会话工具调用次数**计数。达到阈值的轮次结束后触发后台反思，纯聊天不会推进计数。值越小，学习越频繁，启动的子会话也越多。 |
| `AUTOHARNESS_CONSOLIDATE_EVERY_N` | `250` | 整理频率，按同一项目跨会话累计的**主会话工具调用次数**计数。达到阈值后，`Stop` 至多启动一次整理，并保留余数。`0` 表示禁用，负值回退到默认值。 |
| `AUTOHARNESS_DIGEST_EXCHANGES` | `20` | 将当前片段窗口之前的多少轮交互压缩为背景摘要，仅包含文本和工具名。`fork` 模式直接读取真实对话，不使用该摘要。 |
| `AUTOHARNESS_CARRIER` | `bundle` | 反思上下文的承载方式。`bundle` 将脱敏后的片段窗口和摘要交给新子代理；`fork` 恢复并分叉刚结束的会话，让反思者利用父会话已有缓存读取真实对话。在完成缓存命中测量前，默认保持 `bundle`。 |

纯聊天轮次不会推进反思或整理计数。两者同时到期时，`Stop` 优先请求整理，反思所需的活动计数保留到后续 `Stop` 或 `SessionEnd`。后台执行仍受 [运行限制](runtime-controls.md) 约束；发起请求不代表模型任务已完成。

生命周期所用的请求计数仍按轮次累计，不会折算为历史工具调用次数。

### 技能召回

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `AUTOHARNESS_INDEX_SUSPENDED` | `0` | 设为 `1` 后停止 `task` 和 `catalog` 两种模式的技能索引注入。生命周期管理、使用与查看计数、上次运行报告继续工作。 |
| `AUTOHARNESS_RECALL_MODE` | `task` | `task` 在 `UserPromptSubmit` 时对匹配技能排序；`catalog` 在 `SessionStart` 时提供受预算限制的分组目录。不保存查询历史。 |
| `AUTOHARNESS_RECALL_MAX_BYTES` | `4096` | 每次钩子事件中，插件附加上下文的最大 UTF-8 字节数，包含标题和路径提示。`0` 表示不注入。该值只限制插件附加内容，不限制整个会话或宿主原生技能上下文。 |
| `AUTOHARNESS_RECALL_TOP_K` | `5` | 每次最多选取的技能数。任务查询与技能词项没有重合时不注入；超出剩余预算的条目整条跳过。 |
| `AUTOHARNESS_INDEX_DESC_MAX_CHARS` | `60` | 两种召回模式中描述预览的最大字符数，截断时以 `...` 结尾。完整描述仍用于匹配和编写。 |
| `AUTOHARNESS_SKILL_DESC_MAX_CHARS` | `1024` | 创建或更新时，完整描述的独立长度上限，按 Unicode 字符计数。支持中英文触发描述，旧描述仍可通过补丁修复。 |
| `AUTOHARNESS_SKILL_BODY_MAX_LINES` | `25` | `SKILL.md` 正文的非空行数上限。超过上限会被视为会话记录而非技能规则并拒绝；详细材料应放入技能的 `references/`。 |

技能描述支持 `当…时使用`、`用于…` 等中文条件，也支持 `“检查日期边界”` 这样的用户原话。完整描述与展示预览分别限长；预览仅截取前缀，不生成语义摘要。详见 [描述编写与路由](description-routing.md)。

排序算法、召回解释、Token 估算的限制和固定合成测试见 [任务感知召回](task-recall.md)。

### 生命周期

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `AUTOHARNESS_MATURITY_PROJECT` | `100` | 项目层试用期门槛。技能落盘后，所在层累计收到这么多请求时进入转正审查。试用期内正常召回，但不会被归档。 |
| `AUTOHARNESS_MATURITY_GLOBAL` | `300` | 全局层试用期门槛。全局技能跨项目加载，因此默认观察期更长。 |
| `AUTOHARNESS_CAPACITY_PROJECT` | `50` | 项目层成熟技能容量，包含仅被查看过的技能，以及因暂停转正审查而保留的技能。超限时优先归档“使用次数／请求次数”最低的技能；查看次数不提高该比率。试用期技能不占此容量，因此这不是启动索引总量上限。 |
| `AUTOHARNESS_CAPACITY_GLOBAL` | `20` | 全局层成熟技能容量。全局技能影响所有项目，因此默认容量更小。 |
| `AUTOHARNESS_GRADUATION_SUSPENDED` | `0` | 召回不可靠时，可设为 `1` 暂停转正审查。成熟但零使用的技能仍参与容量竞争，可能因容量压力被归档。 |
| `AUTOHARNESS_SNAPSHOT_KEEP` | `5` | 整理者合并前，为每棵技能树保留的运行前快照数量。跨技能合并无法仅靠一次原子重命名完整撤销，因此需要快照。 |

### 运行通知

默认关闭。会话启动时会显示上次运行的摘要，仅包含数量；开启通知后，每次提案队列处理完成即可推送同一份运行结果，并列出技能名称。

通知在运行记录写入、意图队列清空后执行。通知程序缺失、失败或超时可能延迟处理返回，但不会导致技能处理失败或重复执行。

| 环境变量 | 默认值 | 说明 |
|---|---|---|
| `AUTOHARNESS_NOTIFY` | 未设置 | 设为 `desktop` 后启用桌面通知。macOS 使用 `osascript`，Linux 使用已安装的 `notify-send`；工具缺失时静默跳过。通知列出成功落盘和被拒绝的技能，例如 `create foo, patch bar · rejected: baz`。macOS 将通知归于“脚本编辑器”，无通知时可在“系统设置 → 通知”中允许。 |
| `AUTOHARNESS_NOTIFY_CMD` | 未设置 | 自定义通知命令，按命令行参数拆分，不经 shell 执行。通过标准输入接收与 `runs/<run-id>.json` 相同结构的运行记录，通过 `AUTOHARNESS_NOTIFY_SUMMARY` 接收单行摘要，可用于接入 Slack、Webhook 等。技能名称先脱敏；命令带有子会话保护，避免其启动的 `claude` 再被捕获。可与 `desktop` 同时使用。 |
| `AUTOHARNESS_NOTIFY_TIMEOUT_S` | `5` | 每个通知渠道的超时秒数，取整数，最小为 `1`。`/learn` 在宿主的 `Stop` 钩子中处理队列，因此通知也可能使该轮返回延迟，最长受此值限制。 |

### 设置方式

可在启动 Claude Code 的 shell 中设置：

```sh
export AUTOHARNESS_REFLECT_EVERY_N=10
```

也可写入 `.claude/settings.json` 的 `env` 字段：

```json
{ "env": { "AUTOHARNESS_REFLECT_EVERY_N": "10" } }
```

钩子在每次事件中读取环境变量。修改启动环境或配置后，从下一次会话起生效。当前默认阈值仍有待实际使用校准；捕获窗口和暂存文件的字节上限为固定常量，不通过环境变量配置。

解释器选择、后台任务超时、并发和预算限制见 [运行诊断与限额](runtime-controls.md)。
