# 中文触发描述与索引预览

本页对应第 8 步。描述校验仍由 MCP 和确定性执行器共用，不增加模型调用。

## 中文描述可以怎样写

```yaml
---
name: date-boundaries
description: 当需要检查日期格式、跨时区转换与月底边界时使用。
category: testing
---
```

支持常见触发表述：`当…时`、`在…时`、`需要…时`、`遇到…`、`用于…`、`适用于…`、`用来…`，以及常见繁体对应形式。
也可以写用户会说的短语，例如 `用户提出“检查日期边界”则使用。`，或使用 `‘…’`、`「…」`、`『…』`。
英文 `Use when …`、已有英文引号和反引号规则继续可用，中英文可以混写。

`日期格式工具`、`时间处理说明` 这样的纯主题标签仍会被拒绝；空中文引号不能作为触发条件。
这只是确定性语法检查，不是中文语义理解，也不保证覆盖所有自然表达或判断内容是否相关。
技能名称、目录名和 category 继续遵守已有命名规则，本步只扩展描述表达方式。

## 完整描述和索引摘要分别做什么

| 内容 | 用途 | 长度规则 |
| --- | --- | --- |
| 完整 `description` | 保存在 SKILL.md；供宿主及反思/整理的比较索引读取 | create/update 使用 `AUTOHARNESS_SKILL_DESC_MAX_CHARS`，默认 1024 |
| 注入索引摘要 | 任务模式的相关技能列表，或目录模式的启动目录 | 使用 `AUTOHARNESS_INDEX_DESC_MAX_CHARS`，默认 60；超出时截短并附加 `...` |

完整描述不再因为超过 60 字而被拒绝。把索引长度调小不会缩减完整描述上限，调大也不会放宽完整描述上限。
长度按 Python 字符串字符数计算，不是 UTF-8 字节数，也不是模型 Token 数。完整描述上限必须为正整数，非法值会提示并回退默认值。

这里的“摘要”是确定性的前缀预览，不是模型生成的语义摘要。生成时把换行和空白压成一行，避免一条描述伪装成多条索引记录；不会修改原文件。
没有新增需要维护的 summary 字段，也没有批量重写历史技能。短描述照常完整显示，长描述明确标记截断。
反思者和整理者仍获得完整描述作比较；注入索引的显示裁剪不等于原始触发信息丢失。

建议把最重要的触发条件放在前面，尽量简洁。多条条件可以保留在完整描述里，不必为了塞进预览而删掉有用条件。
触发条件过于分散仍需要作者判断是否应拆分技能，语法校验不会替代这个判断。

## 校验与兼容性

MCP 在入队前校验完整描述；绕过 MCP 直接入队，执行器仍会校验。超出完整描述上限、缺少触发线索的 create/update 不会落盘。
凭据、文件路径、技能归属、附件和归档保护保持原有规则，中文触发条件不能绕过它们。
沿用 patch 的历史兼容豁免：已有过长或没有触发线索的技能仍可小步修复。完整替换 update 则按当前规则校验。

本步只解决中文描述的入口兼容和完整描述/显示预览的长度耦合，不宣称已实现语义检索或提升真实召回率。
第 9 步已增加[任务感知排序与单次注入预算](task-recall.md)；第 8 步的描述兼容和独立长度规则继续沿用。
